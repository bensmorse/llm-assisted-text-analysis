LLM-Assisted Analysis of Open-Ended Text

Consumer Car Reviews from Edmunds.com

Intro

Companies commonly collect unstructured textual data containing insights into consumer preferences and behavior (e.g., customer reviews, feedback surveys, support tickets, or other product feedback channels). Historically, quantifying and analyzing these data has been challenging because traditional topic modeling or natural language processing methods are complex, opaque, and not always insightful. The advent of LLMs, however, has dramatically simplified the process of analyzing unstructured text and improved the quality of the resulting output.

This page provides a demonstration of the process by which an analyst can use LLMs to code and quantify unstructured textual data. The process involves four steps:

  1. Define the codes (variables) to be applied to the unstructured textual data.
  2. Using your preferred LLM’s API, submit the unstructured textual data to the LLM alongside prompts for each code. Specify that results be returned in JSON format.
  3. Validate the accuracy of the resulting LLM-coded output against a small subset of human-coded observations. Repeat Steps 1-3 as necessary.
  4. Analyze the resulting quantitative data as desired.

Data

We’ll use data on car reviews scrapped from Edmunds.com and made publicly available on Kaggle. The data contain the review date, vehicle brand, review text and title, and the customer’s overall satisfaction rating on a scale of 0 to 5 for 206,000+ reviews submitted between 2004 and 2018. Our goal is to code the sentiment of each review (pretending that we don’t already have the numeric satisfaction rating), as well as various metrics that we might be interested in tracking overtime, such as whether the review references reliability, safety, drive characteristics, or other variables of interest.

library(ellmer)

chat <- chat_openai(
  model = "gpt-4o-mini",
  system_prompt = "You are a friendly but terse assistant.",
)

# confirm chat is connected to API
chat$chat("Is R a functional programming language?")
Yes, R supports functional programming, allowing functions to be treated as 
first-class citizens, enabling higher-order functions, and facilitating 
functional paradigms. However, it also supports imperative and object-oriented 
styles, making it a multi-paradigm language.
prompt<-paste("Please car review the an owner submitted to Edmunds.com, a popular website for reviewing cars. Review the response carefully and code the following variables:")

response_coded <- type_object(
  prompt,
  sentiment = type_enum("Extract the sentiment of the review", c("positive", "neutral", "negative")),
  gpt_Rating = type_number("Based on this review, how do you think the owner would rate their vehicle? Use a numeric scale from 0 to 5, where 0 is very negative, and 5 is very positive."),
  reliability = type_integer("1 if the owner references the vehicle's reliability in their review, 0 otherwise"),
  utility = type_integer("1 if the owner references the vehicle's utility features in their review, 0 otherwise"),
  driving = type_integer("1 if the owner references the vehicle's driving characteristics in their review, 0 otherwise"),
  comfort = type_integer("1 if the owner references the vehicle's comfort in their review, 0 otherwise"),
  interior = type_integer("1 if the owner references the vehicle's interior features in their review, 0 otherwise"),
  fuel_efficiency= type_integer("1 if the owner references the vehicle's fuel efficiency in their review, 0 otherwise"),
  technology = type_integer("1 if the owner references the vehicle's technology features in their review, 0 otherwise")
)
